## Baseline, before Run 1 (slices 2–10)

- The second evaluator slice adds `IFNA`, `ISBLANK`/`ISNUMBER`/`ISTEXT`/`ISLOGICAL`, `UPPER`/`LOWER`/`TRIM`/`SUBSTITUTE`, `FIND`/`SEARCH`, and `TEXTJOIN`; these are only promoted to `conformance-tested` after shared-fixture parity.

- `SEARCH` currently uses case-insensitive literal matching; Excel wildcard interpretation and locale-specific collation are documented gaps.

- The third lookup slice adds scalar `XLOOKUP`/`XMATCH` exact matching with forward or reverse search, equal-size one-dimensional vectors, lazy `if_not_found`, and explicit rejection of other modes.

- The fourth slice adds `COUNTIF(S)`, `SUMIF(S)`, and `AVERAGEIF(S)` in both engines, with comparison criteria, case-insensitive text, wildcard escapes, blank criteria, and matched logical values in sum ranges. All six have shared conformance cases.

- The fifth slice adds `COUNTBLANK`, `MINIFS`, and `MAXIFS`. The conditional extrema reuse the existing criteria matcher, enforce equal range shapes, ignore nonnumeric result cells, and return zero when no numeric result matches. `COUNTBLANK` counts empty cells and empty text, excluding zero, logicals, and errors. Error-valued cells are represented directly in the Python API and tested against equivalent Rust values.

- The sixth slice adds `TEXTBEFORE` and `TEXTAFTER` with omitted optional arguments, negative instance numbers, case mode, `match_end`, empty delimiters, and lazy `if_not_found`. Matching is scalar-only; locale collation and supplementary-plane character parity with Excel remain unverified.

- The seventh slice adds `ISNA`, `ISERR`, `ISERROR`, and `NA()`. Error predicates distinguish `#N/A` from other supported Excel error values and intercept calculation errors; Workbook Forge' internal unsupported-syntax result remains distinct from an Excel error.

- The eighth slice adds `INT`, `TRUNC`, `ROUNDUP`, `ROUNDDOWN`, `MOD`, and `QUOTIENT`, and aligns `ROUND` precision handling across Python and Rust. Floor, truncation, directed rounding, divisor-sign remainder, and truncating quotient behavior have shared cases. Precision is bounded to -308 through 308; fractional `num_digits` values are truncated toward zero as an implementation rule that still needs direct Excel spot-checking.

- The ninth slice adds `MONTH`, `DAYS`, `EDATE`, and `EOMONTH`, and unifies Python/Rust date-serial conversion around floor-based 1900-system semantics. Shared cases cover serial 60, fractional serials, time-preserving `DAYS`, month-end clamping, leap-year February, fractional month offsets, range errors, and locale text-date rejection. `EDATE` and `EOMONTH` return whole-day serials and discard start-date time fractions as profile behavior that still needs an Excel spot-check.

- The tenth slice adds `IFS` and `SWITCH` with first-match behavior, shape-aware arity checks, defaults, typed scalar comparisons, and shared error/selection cases. Both use ordered short-circuit evaluation as an explicit profile rule; Microsoft does not specify evaluation strictness, so this behavior still needs an Excel spot-check. SWITCH compares ASCII text without case and non-ASCII text exactly; cross-type coercion, locale collation, and array results remain unsupported. The comparison profile also needs an Excel spot-check.
